# 01 设计决策记录

> 只记"为什么"，不记"怎么做"。每条都要能回答「换掉它会付什么代价」。

## D1 · 外壳用 Tauri 2，不用 Electron

**决定**：Rust 后端 + 系统 WebView（Windows 用 WebView2，macOS 用 WKWebView）。

**理由**：这是常驻软件，用户会开着它工作一整天。Electron 的空载基线是 110MB 安装 / 200MB+ 内存，与本项目"轻量"的定位直接冲突。Tauri 的托盘、置顶、透明窗、通知都是原生能力，像素渲染走 Canvas 完全够用。

**代价**：贡献者需要 Rust + 各平台 C 工具链（Windows 需 VS Build Tools 约 2GB）。这是本项目最大的上手门槛，用「M1 探针可以用 Node 跑」来部分抵消——只看数据、不碰 UI 的人不需要 Rust。

## D2 · 主形态是桌面悬浮宠物，托盘只是入口

**决定**：常驻一个 `always-on-top`、无边框、透明背景的小窗口（默认 168×168 舞台，主体球体约 104px，可缩放 1×/2×/3×）。

**形态修订（2026-10-18）**：形象定为**光泽球体（软 3D 渲染）**，由用户提供设计稿，六态靠**光环颜色 + 核心灯色**区分。
→ 原"32×32 像素画布 / ≤8 色调色板 / 8~12fps 帧动画"的规格**作废**，改为**位图精灵（@2x/@3x PNG）+ CSS 合成**：球体、光环、光晕分层叠加，状态切换只换颜色变量与精灵，不做逐帧动画。
→ 代价：素材从"手绘像素帧"变成"3D 渲染导出"，交付方需提供透明底 PNG 多尺寸；同时失去像素风天然的"零成本缩放"，必须按倍数导出以避免糊边。

**理由**：这个产品的价值是"余光可见"。托盘图标只能表达"有新消息"，表达不了"它正在工作/它卡住了"这种持续状态。而状态需要被无意识地感知，所以必须占用屏幕空间——只是要小、要能吸附边缘、要能一键隐藏。

**代价**：必须处理多显示器、全屏应用遮挡、点击穿透、macOS 全屏 Space 切换等问题。这些工作在 M2 里占的比重会超过形象本身。

## D3 · 只监测本机

**决定**：不聚合多机，不请求网络，不接云端账号体系（积分余额 provider 留接口，默认不启用）。

**理由**：本机数据本身已经能回答"我现在有几件事在跑、花了多少"。加云端就引入账号、隐私、以及"你的助手在往外发东西"的信任成本。开源工具最贵的是信任，不是功能。

**代价**：换机器看不到历史。可接受。

## D4 · 只读，且绝不碰 WAL 的写路径

**决定**：`workbuddy.db` 以 `?mode=ro` 打开；不执行 `PRAGMA wal_checkpoint`、不建表、不迁移、不写任何文件到 `~/.workbuddy`；探针的差分状态写在项目自己的 `probe/state/` 下。

**理由**：那是 WorkBuddy 自己的生产数据库。一个第三方小工具如果触发 WAL checkpoint 或写锁，最坏情况是让主程序卡住甚至损坏会话——这个风险不能为了省事去赌。同时这也让"卸载 = 删一个文件夹"成立。

**代价**：只读连接拿不到主库最新页以外的内容（WAL 未 checkpoint 的部分靠 -shm 索引，实测可读）；如果 WorkBuddy 未来给 db 加密，本方案直接失效，需要降级到只剩文件源。

## D5 · 探针先行（M1），契约冻结后才写 UI

**决定**：M1 不写任何 Tauri 代码，只交付一个能跑的数据探针 + 一份数据契约文档。

**理由**：`credit_json` 是 map、`used/size` 是上下文占用而非积分、span 名即工具名——这些语义没法靠猜，只能实测。契约错了，后面所有状态机和动画都会建在错的信号上。而这个项目 90% 的风险就在"数据到底长什么样"。

**代价**：M1 看起来"没有界面"，对围观者不直观。

## D6 · 采集与渲染分离，跨进程不共享状态

**决定**：采集在 Rust 侧线程（1s 轮询 + 文件事件），通过 Tauri 事件把**增量事件**推给前端；前端只维护展示所需的最小状态。

**理由**：像素动画掉帧不能导致漏事件；反过来，前端崩溃重启后靠后端 replay 最近事件就能恢复。也让 M1 的探针逻辑能一比一移植（纯函数：文件 → 快照）。

**代价**：多一层事件协议要维护（`credit` / `state` / `stuck` / `done`）。

## D7 · 积分只做"消耗"，不做"余额"

**决定**：UI 展示本次消耗、今日累计、燃速（积分/分钟）、会话排行。余额留可插拔 provider，M4 前不实现。

**理由**：本地 `settings.json` 与 db 里都没有 quota/balance 字段（已核实）。硬编一个余额数字等于给用户看假数据，比不显示更糟。

**代价**：首版会被问"我还剩多少积分"。答案写在 README 里，而不是编一个。
